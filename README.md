# V2 — HWP / HWPX / HTML / PDF 변환 공장 (완성)

한글(HWP 5.0)·HWPX·HTML 문서를 서로 바꾸고 PDF 로 내보내는 변환기와, 변환 품질을 숫자로 재는 평가 도구 모음입니다. 웹 화면(Streamlit)에서 파일을 올리면 형식을 알아내 원하는 형식으로 내려줍니다. 모든 처리는 내 컴퓨터(컨테이너) 안에서만 일어납니다.
V1(처음 발표한 버전)에서 PDF 출력, 한컴 저장 줄 끊김 따르기, 차트·그림·떠 있는 개체 처리, 평가 도구와 회귀 기준선을 더했습니다. V2 는 여기서 완성으로 보고, 이후 개선은 V3(글자 폭·줄 나눔·쪽 나눔)와 V4(웹 문서 편집) 브랜치에서 이어집니다.

> 한글과컴퓨터(한컴)와 무관한 독립 프로젝트입니다. "한글", "한컴", "HWP" 는 각 권리자의 상표·명칭이며, 이 저장소는 공개된 파일 형식 문서와 실제 파일 관찰에 근거해 만들었습니다.

## 지원하는 변환

| 입력 \ 출력 | HTML | HWPX | PDF |
|---|---|---|---|
| **HWP** (5.0) | ✓ 자체 변환기 | ✓ [hwp-cli](https://github.com/STAIxBWLB/hwp-cli) 직접 변환(없거나 실패하면 자체 변환기) | ✓ |
| **HWPX** | ✓ 자체 변환기 | — | ✓ |
| **HTML** | — | ✓ 자체 변환기(`html2hwpx.py`) | ✓ |

- PDF 는 HTML 을 [WeasyPrint](https://weasyprint.org/) 로 찍습니다. 한컴·마이크로소프트 글꼴 파일은 넣을 수 없어서 무료 나눔 글꼴(SIL OFL)로 대신하고, 글자 폭 차이는 보정합니다.
- HWP 가 한컴이 **저장해 둔 줄 끊김·줄 높이**를 가지고 있으면 PDF 에서 그대로 따릅니다(쪽 수·글 위치가 한컴에 가까워집니다).
- 암호·배포용·DRM 이 걸린 문서와 HWP 3.0 은 거절합니다.
- 선택 기능: 문서 맨 위 오른쪽에 결재선 표 넣기(`--approval 담당,검토,확인,승인`).

## 빠른 시작

필요한 것: Docker.

```sh
docker compose up -d --build        # http://localhost:8501  (이 컴퓨터에서만 접속됨)
```

명령줄로 바로 바꾸려면(컨테이너 안 또는 의존성을 깐 환경에서):

```sh
python convert.py 입력.hwp 출력.html      # .html | .hwpx | .pdf
```

이 환경에서 되는 변환·옵션·한도·종료 코드를 기계가 읽는 JSON 으로 보려면: `python convert.py --capabilities`

보안 설정: 읽기 전용 파일시스템, 비루트 사용자, `cap_drop: ALL`, 메모리 3GB 제한, 외부 자원 접근 차단(`data:` 주소만 읽음). 업로드 상한 100MB, 동시 변환 3건, 변환 제한 시간 120초.

| `devtools/` | 평가·진단 도구(쪽 수·글 위치·모양 유사도·표 행 높이·쪽 대응 등). 사용법은 `devtools/README.md` |
| `test_hwpx_roundtrip.py` | 회귀 시험(왕복 변환, 표·글꼴·쪽 번호 등 규칙 검사) |
| `tools/` | 외부 도구의 **출처·체크섬·라이선스 파일**만 있습니다(실행 파일은 올리지 않음. 컨테이너 빌드 때 공식 릴리스를 받아 체크섬이 맞을 때만 설치) |

## 개발 방식

한 번에 한 가지씩, 아래 한 사이클을 돕니다.

1. 문서에서 **결함의 종류**를 찾아 일반적으로 고칩니다(개별 문서에 맞춘 땜질은 하지 않습니다).
2. `sh devtools/run_layout.sh` — 공개 정답지 20건의 쪽 수 일치(기준 18/20 이상)
3. `python test_hwpx_roundtrip.py` — 회귀 시험
4. `sh devtools/run_eval.sh <세트>` — 쪽 수·글 보존·글 위치 오차·모양 유사도 평가(앱과 같은 글꼴의 격리 컨테이너, 네트워크 없음)
5. `python devtools/eval_summary.py` — 세 세트를 기준선(`devtools/gates.json`)과 비교해 ✓/✗ 로 보여 줌, 나빠진 문서는 `evaldiff.py` 로
6. `docker compose up -d --build` 후 컨테이너에서 변환 확인

독립 증거(개발에 쓰지 않은 사용자 문서)가 후퇴하면 그 수정은 켜지 않습니다. 평가 도구는 시험 문서(`corpus/`)와 한컴 정답 PDF 가 있어야 돌아가며, 이 저장소에는 포함하지 않습니다.

## V2 최종 정확도 (기준선 `devtools/gates.json`, 2026-10-14)

정답지는 한컴이 만든 PDF 이고, 같은 HWP 도 한컴 버전·OS·글꼴에 따라 쪽 나눔이 달라질 수 있어 **절대적 정답이 아니라 비교 기준**입니다.

| 평가 세트 | 쪽 수 일치 | 모양 유사도 |
|---|---|---|
| 공개 문서 102건(rhwp 저장소 샘플 중 정답 PDF 가 있는 것, 정답 의심 6건 제외) | 66건 | 0.511 |
| 공개 문서 20건 | 16/16 (의심 정답 4건 제외) | 0.669 |
| 사용자 문서 8건(개발에 쓰지 않은 독립 증거, 저장소에는 없음) | 8/8 | 0.633 |
| HTML→PDF 20건(기준은 한컴이 아니라 Edge 인쇄) | 17/20 | 0.541 |

- 정답지 PDF·공개 문서 샘플은 이 저장소에 **포함하지 않습니다**. 평가를 직접 돌리려면 [rhwp](https://github.com/edwardkim/rhwp) 저장소의 샘플을 받아 `corpus/` 에 두는 구조입니다.
- 모양 유사도는 15pt 격자 잉크 겹침이라 글자 모양(글꼴) 차이는 거의 잡지 못합니다.

## 알려진 한계

- **글꼴:** 한컴 글꼴이 없는 환경의 PDF 는 나눔 글꼴로 찍혀 글자 모양이 다릅니다. HTML·HWPX 는 글꼴 이름만 적으므로 보는 PC 에 그 글꼴이 있으면 그대로 보이고, 없으면 그 PC 의 기본 한글 글꼴(윈도는 대개 맑은 고딕)로 바뀌어 글자 모양과 줄 바꿈이 달라집니다. 한컴 오피스가 깔린 PC 라도 한컴 글꼴을 전부 브라우저가 쓸 수 있는 것은 아닙니다.
- **쪽 나눔:** 표가 쪽을 넘는 위치, 떠 있는 개체, 다단 문서 등에서 한컴과 쪽 수·줄 위치가 다른 문서가 있습니다.
- HTML→PDF 는 줄을 새로 흘려 쓰므로 HWP·HWPX 에서 바로 PDF 로 갈 때보다 한컴과 줄 끊김이 더 자주 달라집니다.

이 프로젝트는 사람(작업지시자)이 방향·품질·결정을 맡고 [Claude Code](https://claude.com/claude-code) 가 분석·구현을 도우며 만들었습니다. AI 출력을 읽지 않고 받아들이지 않고, 아래 규칙을 `CLAUDE.md` 에 두었습니다.

- 사용자 문서를 외부 서비스(API)로 보내려면 **먼저 승인**을 받는다. 시각 검수는 공개 코퍼스만.
- `requirements.txt` 수정, 새 외부 실행 파일 도입은 먼저 묻는다(공식 릴리스 + 체크섬 확인).
